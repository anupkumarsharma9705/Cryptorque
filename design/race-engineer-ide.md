## Problem Statement

The current portfolio presents a backend developer through a familiar hero + cards template. It lists technologies but does not show how the engineer thinks, what was measured, or what trade-offs were made. For a hiring manager, design engineer, or security-minded reviewer, the page does not answer the only question that matters: **can this person build and defend a real system?**

The rebuild must make the work legible in three seconds and inspectable for thirty minutes.

## What Makes This Cool

A portfolio that behaves like a **race engineer's telemetry workstation crossed with a code editor**.

- The visitor is not scrolling a marketing page. They are inspecting a system.
- `Cmd/Ctrl + K` opens a command palette that navigates the entire portfolio like an IDE.
- `g` + section key jumps between sections; `t` toggles theme; `?` shows the keyboard map.
- A persistent status bar reports the active module, theme, local IST clock, and build state.
- FinGateway is presented as a P0 case study with a live-looking telemetry panel, a 7-stage request pipeline, a STRIDE model, k6 evidence, and honest known limitations.
- Every claim has an artifact behind it. No percentage proficiency bars. No invented production experience.

The "whoa" moment: a senior reviewer presses `⌘K`, types "threat", and lands inside a real threat model instead of a hero section.

## Constraints

- **Credibility first.** Early-career engineer, 2025 graduate. No claims of production scale, Kubernetes operations, or years of tenure that the evidence does not support.
- **Premium, not busy.** 50% technical depth, 30% motorsport telemetry, 20% cyber threat intelligence. Sharp geometry, restrained motion, one signature interaction.
- **Dark by default, light required.** Both themes must pass contrast checks. No flash on load.
- **Performance.** No UI framework dependency. Static build, inline SVG icons, optimized images, system-friendly fonts.
- **Accessibility.** Keyboard-complete, visible focus, skip link, reduced-motion support, accessible dialogs and tabs.
- **Honest contact.** The form composes a `mailto:` message instead of pretending to call a backend that does not exist.

## Premises

1. A hiring manager will give the page 10–30 seconds unless something rewards a second look.
2. Engineers trust evidence more than adjectives. Load-test numbers, ADRs, and known failure modes outperform a longer skills list.
3. The motorsport metaphor should shape **information design** (sectors, telemetry, timing, status) — not just decoration.
4. The security story is strongest when it includes what is **not** solved yet.
5. Keyboard navigation is a credible signal for a backend engineer because it demonstrates systems thinking and respect for power users.

## Approaches Considered

### Approach A: Race Engineer's IDE — full rebuild (selected)
Custom React + Vite design system. Telemetry-first hero, IDE shell, command palette, keyboard map, evidence-backed case studies, artifact viewer. Highest craft ceiling; the system itself becomes a portfolio piece.

### Approach B: Telemetry layer — progressive enhancement
Keep the existing layout and add a command palette, status bar, and metric cards. Faster, but the IDE metaphor feels bolted on and the existing visual system fights it.

### Approach C: Security operations console
Reframe everything as a SOC dashboard: projects as incidents, skills as detection rules, MITRE tags. Distinctive, but risks narrowing the audience and reading as security theater.

## Recommended Approach

**Approach A.** The user has time, wants to impress senior engineers, and explicitly asked for the telemetry console and IDE concepts to be combined. A native rebuild is the only way the interaction model feels intentional.

## Success Criteria

- A first-time visitor understands the positioning — security-first backend engineer, fintech gateways, measured rigor — within one viewport.
- Every headline metric traces to a named source (k6 run, ADR, threat model).
- `⌘K`, section navigation, theme toggle, and all dialogs work with keyboard only.
- Dark and light themes both look deliberate and pass WCAG AA for body text.
- `npm run build` succeeds; no console errors; responsive at 375, 768, 1024, 1440.
- The page feels premium because of restraint, not because of effects.
